Herencia y Polimorfismo

Completada

La herencia permite crear una clase hija (subclase) que reutiliza atributos y métodos de una clase padre (superclase). Se usa la palabra clave extends.

La subclase hereda todo lo que no sea private del padre. Para que los atributos del padre sean accesibles directamente en la hija, se declaran protected.

En Java solo se puede extender una clase (herencia simple). La relación que establece es "es un" (is-a): un Becado es un Alumno. Esto es diferente de la relación "tiene un" (has-a), que se modela con atributos, no con herencia — por ejemplo, un Auto tiene un Motor.

Atención: dos clases que casualmente comparten los mismos campos no deben heredar entre sí si no existe esa relación conceptual real.

Cuando la superclase tiene un constructor con parámetros, la subclase debe llamarlo explícitamente con super(). Esta llamada debe ser la primera línea del constructor hijo.

Si no se llama a super(), Java intenta llamar al constructor sin parámetros del padre — si ese no existe, el compilador da error. 

public class Alumno {
    private String nombre;
    private int    grado;
    private double cuota;

    public Alumno(String nombre, int grado, double cuota) {
        this.nombre = nombre;
        this.grado  = grado;
        this.cuota  = cuota;
    }

    public double cuotaNeta() { return cuota; }
}

public class Becado extends Alumno {
    private double saldoBeca;

    public Becado(double beca, String nombre, int grado, double cuota) {
        super(nombre, grado, cuota);  // ← primera línea obligatoria
        saldoBeca = beca;
    }
}

La palabra clave super tiene tres usos posibles: 

super(args)         // 1. Invocar el constructor del padre (primera línea)
super.metodo(args)  // 2. Invocar un método del padre (ej: super.toString())
super.atributo      // 3. Acceder a un atributo del padre (si es protected)

La sobreescritura permite que una subclase redefina un método heredado con su propio comportamiento. @Override no es obligatoria pero es una buena práctica: si el nombre del método no coincide con ninguno del padre, el compilador avisa el error de inmediato.

Para que haya sobreescritura, la firma del método debe ser idéntica a la del padre. La firma está formada por el nombre y la lista de parámetros (número, tipo y orden). No forman parte de la firma: el tipo de retorno, el modificador de acceso ni los nombres de los parámetros.

Un caso muy común es sobreescribir toString() para que imprimir un objeto muestre información útil. También se pueden sobreescribir métodos de negocio como cuotaNeta(): 

public class Becado extends Alumno {
    private double saldoBeca;
    // ... constructor con super() ...

    @Override
    public String toString() {
        return super.toString() + ", beca: " + saldoBeca;
    }

    @Override
    public double cuotaNeta() {
        return super.cuotaNeta() - saldoBeca;
    }
}

super.toString() reutiliza la implementación del padre y le agrega la info propia. Lo mismo con super.cuotaNeta(): el becado paga la cuota normal menos su beca.

La herencia puede encadenarse en varios niveles: A → B → C, donde C hereda de B, que hereda de A. Cada super() sube un nivel en la cadena.

Ejemplo: Electrodomestico → Lavadora. La Lavadora hereda marca y potencia de Electrodomestico, agrega capacidad, y sobreescribe getInfo() usando super.getInfo(): 

public class Electrodomestico {
    protected String marca;
    protected int    potencia;
    public Electrodomestico(String m, int p) { marca = m; potencia = p; }
    public String getInfo() { return marca + " - " + potencia + "W"; }
}

public class Lavadora extends Electrodomestico {
    private int capacidad;
    public Lavadora(String m, int p, int c) {
        super(m, p);            // inicializa Electrodomestico
        this.capacidad = c;
    }
    @Override
    public String getInfo() {
        return super.getInfo() + ", Capacidad: " + capacidad + "kg";
    }
}

Regla clave: super() siempre va primero en el constructor. Java no permite herencia múltiple (extender dos clases a la vez); para eso existen las interfaces.

La sobrecarga de métodos (overloading) consiste en definir varios métodos con el mismo nombre pero diferente firma dentro de la misma clase. Recordá: la firma = nombre + lista de parámetros (número, tipo, orden).

Es diferente de la sobreescritura: la sobrecarga ocurre en la misma clase, entre métodos con diferente firma. La sobreescritura ocurre entre subclase y superclase, redefiniendo un método con la misma firma. 

public class Empleado {
    private double salario;

    // Sobrecarga: mismo nombre, distintos parámetros
    public double calcularSalario() {
        return salario;
    }
    public double calcularSalario(double bono) {
        return salario + bono;
    }
    public double calcularSalario(double bono, double deduccion) {
        return salario + bono - deduccion;
    }
}

En el main, Java elige automáticamente cuál versión llamar según los argumentos que pasás: 

Empleado e = new Empleado(2000);
e.calcularSalario();              // retorna 2000
e.calcularSalario(500);           // retorna 2500
e.calcularSalario(500, 100);      // retorna 2400
🔁 Resumen: Sobrecarga vs Sobreescritura
Sobrecarga: misma clase · mismo nombre · diferente firma · en tiempo de compilación
Sobreescritura: subclase/superclase · misma firma · diferente comportamiento · en tiempo de ejecución
